# AI Engine — Complete Reference

## Architecture

The AI system uses a **multi-provider plugin architecture** with automatic fallback. When a provider fails (API key missing, rate limited, network error), the next provider in the chain is tried automatically.

```
User Request
    ↓
AIService (src/services/ai/ai-service.ts)
    ↓
AIEngine (src/ai/ai-engine.ts)
    ↓
    Try providers in order:
    Groq (default) → OpenAI → Anthropic → Gemini
    ↓
Log to AIGeneration table on success
    ↓
Return parsed response to caller
```

---

## Provider Chain

| Provider | File | SDK | Default Model | Priority |
|----------|------|-----|---------------|----------|
| **Groq** | `providers/groq-provider.ts` | REST API (`groq.com/openai/v1`) | `llama-3.1-8b-instant` | 1st (default) |
| **OpenAI** | `providers/openai-provider.ts` | `openai` npm SDK | `gpt-4o` | 2nd |
| **Anthropic** | `providers/anthropic-provider.ts` | REST API (`anthropic.com/v1`) | `claude-3-5-sonnet-20241022` | 3rd |
| **Gemini** | `providers/gemini-provider.ts` | `@google/generative-ai` SDK | `gemini-2.0-flash` | 4th |

The preferred provider can be configured by setting `PREFERRED_AI_PROVIDER` env var.

## AI Engine Methods

### `generate(request: AIGenerationRequest, userId: string, generationType: AIGenerationType)`
Core generation method. All other methods delegate through this.

**Flow**:
1. Iterates providers in priority order
2. For each: checks if API key configured → calls `provider.generate(request)`
3. On success: logs `{ prompt, response, model, tokens }` to `AIGeneration` table
4. On failure: catches error, tries next provider
5. If all fail: returns empty/fallback response

### Feature Methods

#### `breakDownGoal(goal: string, userId: string)`
**Prompt**: "Break down this goal into actionable missions..."
**Returns**: `AiBreakdownResult { title: string, missions: AiBreakdownMission[] }`
**Each mission**: `{ title, description, difficulty, estimatedTime?, category?, tags? }`

#### `generateMissionsFromContext(context: string, userId: string)`
**Prompt**: Contextual mission generation from user's goal description.
**Returns**: `AiBreakdownMission[]`

#### `generateWeeklyPlan(userId: string)`
**Pre-fetch**: Loads user's pending/active missions + active campaigns
**Prompt**: "Create a weekly plan distributing these missions across days..."
**Returns**: `AiPlanResult { days: { day: string, focus: string, missions: string[] }[] }`

#### `generateDailyBriefing(userId: string)`
**Pre-fetch**: Today's missions (pending), pending count, streak, level, total missions completed
**Prompt**: "Generate an inspiring daily briefing..."
**Returns**: Markdown string with greeting, mission summary, encouragement

#### `getProductivityCoaching(userId: string, question?: string)`
**Pre-fetch**: Focus stats, recent missions
**Prompt**: Contextual coaching advice based on user's question or general productivity tips
**Returns**: Coaching advice string

#### `getMotivation(userId: string, context?: string)`
**Pre-fetch**: Current streak, progress level
**Prompt**: "Generate a short, powerful motivational message..."
**Returns**: Short motivational quote string

#### `checkProviderHealth()`
Checks which providers have API keys configured by checking env vars:
- `GROQ_API_KEY`
- `OPENAI_API_KEY`
- `ANTHROPIC_API_KEY`
- `GEMINI_API_KEY`

**Returns**: `Record<string, boolean>` (e.g., `{ groq: true, openai: false, anthropic: false, gemini: false }`)

## Data Storage

Every successful AI generation is logged to the `AIGeneration` table:
```prisma
model AIGeneration {
  id        String   @id @default(uuid())
  userId    String
  type      String   // goal_breakdown, mission_gen, weekly_plan, daily_plan, coaching, motivation
  prompt    String   // The input prompt
  response  String   // The AI response
  model     String   // Model used (e.g., "gpt-4o", "llama-3.1-8b-instant")
  tokens    Int?     // Token count (if available)
  metadata  Json?
  createdAt DateTime @default(now())
}
```

## Error Handling

- Each provider call is wrapped in try/catch
- On failure: logs error, tries next provider in chain
- If all providers fail: AI features gracefully return fallback content (empty string or cached data)
- Provider key check (`checkProviderHealth`) is available via the `/api/health` route and UI
